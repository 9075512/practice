# 背题库 · 架构设计

## 1. 目标与边界

**只做一件事：把 Excel 里的题目导入，然后在手机上按题库和题型翻卡背诵。**

明确不做：

- 章节、分类、知识点、标签等层级
- 用户注册资料、练习记录、成绩、错题本
- 做题判分、统计报表、排行榜
- 题目与题库的手工批量录入（单题微调除外）
- 会员到期、续费、分级（卡密激活即永久）

用户体系只保留最小实现：用户名 + 密码注册产生 `app_user`，唯一用途是承载 VIP 会员关系（单点登录：同一账号只允许一台设备在线）；背诵进度与掌握标记仍在手机本地。

因此核心数据模型是：管理员、题库、题目，加上用户与卡密会员。题型是题目上的一个字段，不是独立实体。

---

## 2. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 服务端 | Node 22 + Express 4 | 单进程、零外部服务，`npm start` 即用 |
| 数据库 | SQLite（WAL） | 单文件、免部署；better-sqlite3 缺失时回退 `node:sqlite` |
| Excel | SheetJS（xlsx） | 同时支持 .xlsx / .xls，读写模板 |
| 后台 | Vue 3 + Vite + Element Plus | 三个列表页，组件够用且体积可控 |
| 移动端 | 零构建原生 H5（ES Module） | 不用打包，Express 直接托管在 `/m/`；底部三 Tab |

后台构建产物输出到 `server/public`，由 Express 同源托管，部署只有一个端口。

## 3. 数据模型

```
admin_user
  id, username, password_hash, display_name, role, status, last_login_at, ...

bank
  id, name, description, vip_only, sort_order, deleted_at, created_at, updated_at
  UNIQUE(name) WHERE deleted_at IS NULL

question
  id, bank_id → bank.id, type, stem, options(JSON), answer, analysis,
  sort_order, deleted_at, created_at, updated_at

app_user
  id, identity_type(device), identity_value(acct:<username>), nickname,
  username UNIQUE, password_hash, session_id, status, created_at, last_login_at
  UNIQUE(identity_type, identity_value)
  session_id：唯一在线会话号，每次登录覆盖，令牌内的 sid 与它不一致即视为被挤下线

card_batch
  id, batch_no, name, quantity, valid_until, note, created_by, created_at

card_key
  id, batch_id → card_batch.id, code_hash(HMAC-SHA256), code_tail(末4位),
  status(unused | used | void), valid_until, used_by_user_id → app_user.id,
  used_at, voided_at, void_reason, created_at
  UNIQUE(code_hash)；used_by_user_id 唯一（一卡只能被一人使用）

vip_membership
  id, user_id → app_user.id UNIQUE, level('permanent'),
  source('card' | 'admin'), source_card_id → card_key.id UNIQUE(可空), source_admin_id → admin_user.id,
  activated_at, created_at
  没有 expires_at：永久性由结构保证
  source=card 来自卡密激活；source=admin 是后台手动设置身份（不占卡密，source_card_id 为空）

card_activation_log
  id, card_id, user_id, code_tail, result, message, client_ip, user_agent, created_at
```

### 关键约定

- **题型存中文**：`单选题 / 多选题 / 判断题 / 填空题 / 简答题`。导入时把 `single`、`单选`、`单项选择题` 等写法归一，筛选无需映射表。
- **选项存 JSON 数组**：`[{"key":"A","text":"..."}]`，最多 A~H。判断题导入时自动补 `A 正确 / B 错误`。
- **答案存展示文本**：单选 `A`，多选 `AC`，判断 `正确`，填空/简答为原文。背题只展示，不做判分。
- **软删除**：题库与题目都有 `deleted_at`。删题库时在同一事务内软删其题目。题库名称唯一索引带 `WHERE deleted_at IS NULL`，删掉后可用同名重建。
- **不建章节表**：题目的顺序由 `sort_order` 维护，导入时按行号递增。

旧版数据库（`bank.title`、英文题型、章节表）在启动时自动迁移：

1. 读出旧 `bank` / `question`，把旧表改名为 `legacy_*`，删除章节、分类、标签、练习相关表；
2. 建新表；
3. 题库 `title → name`；题目 `single/multiple/judge/fill → 中文题型`；JSON 答案数组转展示文本；判断题选项统一为正确/错误；
4. 删除 `legacy_*`。

迁移只在检测到旧结构时执行一次，重复启动不会重复写入。

## 4. 接口契约

统一响应：`{ code, message, data }`，成功 `code = 0`。分页：`{ list, total, page, pageSize }`。

### 4.1 移动端（需 `X-User-Token`，注册 / 登录除外）

| 方法 | 路径 | 参数 | 返回 |
|---|---|---|---|
| POST | `/api/mp/auth/login/password` | `{ username, password }` | `{ token, expiresAt, user, vip }`；旧会话立即失效 |
| POST | `/api/mp/auth/register` | `{ username, password, nickname? }` | 同上（注册即登录） |
| POST | `/api/mp/auth/logout` | — | `{ loggedOut }`；清空会话号 |
| GET | `/api/mp/vip/status` | — | `{ isVip, level, activatedAt, cardTail }` |
| POST | `/api/mp/vip/activate` | `{ code }` | `{ isVip, level, activatedAt, alreadyActivated, cardTail }` |
| GET | `/api/mp/banks` | — | 题库数组；VIP 专属库对非会员 `locked: true` |
| GET | `/api/mp/banks/:id` | — | 单个题库 |
| POST | `/api/mp/questions/query` | 见下 | `{ list, total, page, pageSize, hasMore }`；非会员取 VIP 库返回 403 / `VIP_REQUIRED` |

`questions/query` 参数：

```json
{
  "bankId": 1,
  "type": "单选题",
  "order": "seq | random",
  "seed": 20261019,
  "page": 1,
  "pageSize": 100,
  "excludeIds": [12, 18]
}
```

- `type` 为空表示全部题型。
- `excludeIds` 用于「只看未掌握」，客户端传入本地已掌握题目 ID，服务端用 `NOT IN` 排除（最多 5000 个）。
- `order=random` 时排序为 `((id * 1103515245 + seed) & 2147483647)`，同一 `seed` 下顺序稳定，因此分页不会重复或漏题。`seed` 由客户端每次进入背题页生成一次（当前 H5 直接整份取回后本地洗牌，接口仍保留 seed 能力）。

### 4.2 后台（需 `X-Admin-Token`）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/admin/auth/login` | `{ username, password }` → `{ token, expiresAt, admin }` |
| GET | `/api/admin/banks?keyword=` | 题库列表 |
| GET | `/api/admin/banks/options` | 下拉选项（id / name / questionCount） |
| POST | `/api/admin/banks` | 新建 `{ name, description, sortOrder, vipOnly }` |
| PUT | `/api/admin/banks/:id` | 更新 |
| DELETE | `/api/admin/banks/:id` | 软删除题库及其题目 |
| GET | `/api/admin/questions` | `bankId / type / keyword / page / pageSize` |
| GET | `/api/admin/questions/:id` | 单题详情 |
| PUT | `/api/admin/questions/:id` | 更新题型、题干、选项、答案、解析 |
| DELETE | `/api/admin/questions/:id` | 软删除单题 |
| GET | `/api/admin/import/template` | 下载模板（xlsx 二进制） |
| POST | `/api/admin/import/preview` | 解析并返回预览 |
| POST | `/api/admin/import/commit` | 确认导入 |
| GET | `/api/admin/card-batches` | 批次列表（含使用统计） |
| POST | `/api/admin/card-batches` | 生成 `{ name, quantity ≤ 2000, validUntil?, note? }`，明文仅本次返回 |
| GET | `/api/admin/card-batches/:id` | 批次统计 |
| GET | `/api/admin/card-batches/:id/cards` | 卡密明细 `{ batch, list, total, page, pageSize }` |
| POST | `/api/admin/card-batches/:id/void` | 整批作废未使用，返回 `{ voided }` |
| POST | `/api/admin/cards/:id/void` | 单卡作废（仅 unused 可作废） |
| GET | `/api/admin/vip-members` | VIP 名单，支持昵称 / 身份 / 卡密尾号 / 用户 ID 搜索 |

鉴权：管理员与用户令牌均为 `payload.signature` 的 HMAC-SHA256 无状态令牌（`X-Admin-Token` / `X-User-Token`），分类型签发、不可互用；管理员默认 12 小时，用户 7 天。服务重启不失效。

## 5. Excel 导入流程

### 5.1 两段式

```
选择文件
  → 浏览器 FileReader 读为 base64
  → POST /import/preview  { base64, fileName, mode, targetBankId? }
  → 服务端解析、校验、查重，缓存原始 buffer 30 分钟，返回 importId
  → 前端展示统计 + 前 20 行 + 错误/重复明细
  → POST /import/commit   { importId, mode, targetBankId? }
  → 服务端用缓存的 buffer 重新解析（保证与预览一致）+ 再查一次重
  → 事务内建题库、插题目
```

上传使用 base64 JSON 而非 multipart，是为了不引入 multer；`express.json` 上限 20MB，对应原文件约 10MB。

### 5.2 解析规则

1. 优先取工作表名包含「题目」或「题库」的 sheet，否则取第一个。
2. 扫描前 20 行找表头：必须能识别「题干」，且至少命中 2 个已知列。支持别名：
   - 题库：题库 / 题库名称 / 所属题库 / 科目 / 分类
   - 题型：题型 / 题目类型 / 试题类型 / 类型
   - 题干：题干 / 题目 / 问题 / 试题 / 题目内容
   - 答案：答案 / 正确答案 / 参考答案 / 标准答案
   - 解析：解析 / 答案解析 / 试题解析 / 说明 / 备注
   - 选项：选项A ~ 选项H
3. 逐行清洗：去首尾空白、全角空格、`\r\n`。空行跳过，行号按 Excel 实际行号记录。
4. 题型归一；题型为空时推断：
   - 有 ≥2 个选项且含「正确/错误」→ 判断题
   - 答案含多个选项字母 → 多选题
   - 有选项 → 单选题
   - 答案为对/错 → 判断题
   - 否则短答案 → 填空题，长答案 → 简答题
5. 答案归一：
   - 判断题：对/是/√/T/1 → 正确；错/否/×/F/0 → 错误；也支持字母通过选项文本映射
   - 单选/多选：优先匹配选项文本，其次提取 A~H 字母并校验是否在选项内；单选多个字母直接报错
6. 查重键：`题库 + 题型 + 去除空白和常见标点后的题干`。同时检查数据库已有题目与文件内重复。
7. 异常行只跳过并记录原因，不阻断整份文件。单次最多 20000 行。

### 5.3 导入模式

- `excel`：按表格「题库」列分库，不存在的题库自动创建。
- `target`：忽略题库列，全部写入 `targetBankId` 指定的题库。

## 6. 背诵流程与本地状态

### 页面

```
题库列表 → 选择题型/顺序/是否只看未掌握 → 翻卡背诵
```

### 翻卡交互

- 默认只显示题干与选项；点「显示答案」后揭示答案，选中的选项高亮。
- 上一题 / 下一题；进度条按 `(index+1)/total` 计算。
- 一次取 100 道，当前索引接近末尾时自动取下一页并拼接。
- 顺序模式用 `sort_order, id`；随机模式用固定 `seed`。

### 本地存储（不上传）

| key | 内容 |
|---|---|
| `recite_mastery_v1_<bankId>` | `{ [questionId]: 1 }`，标记已掌握 |
| `recite_progress_v1_<bankId>_<type>_<order>_<all\|unmastered>` | 上次背到的索引 |

「继续背题（第 N 题）」读取进度键；「从头开始」传 `start=0`。标记掌握后，下次以「只看未掌握」进入时该题会被 `excludeIds` 排除。

## 8. 验证

`cd server && npm run smoke`

测试会启动一个使用临时数据库和随机端口的服务（`NODE_ENV=test`），覆盖：

- 健康检查、未登录 401、错误密码、管理员登录
- 模板表头、Excel 预览统计、确认导入、题库/题型筛选
- 用户设备登录、伪造令牌拒绝、非会员锁定态（403 / VIP_REQUIRED）
- 卡密生成（格式、唯一性）、数据库只存 HMAC 哈希不存明文
- 激活成功、小写/带分隔符输入归一、同卡重复提交幂等
- 已是 VIP 不消耗新卡（40913）、作废卡 40911、过期卡 40912、无效卡 40410
- 4 用户并发抢同一张卡：仅 1 个成功，其余 40910，会员记录唯一
- VIP 会员解锁 VIP 题库、管理端名单与批次/单卡作废
- 数据完整性：无「已使用未开卡」孤儿、会员与使用人一致、审计日志存在

结束后自动关闭服务并删除临时库，不影响 `data/app.db`。
