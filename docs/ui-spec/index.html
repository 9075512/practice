练题云界面设计规范

从练题系统后台沉淀的一套浅色中后台视觉体系：以克制的蓝色品牌色、清晰的信息层级和稳定的列表密度为核心， 覆盖色彩、排版、布局、组件、图表与移动端适配。本文档中的数值均取自线上系统，可直接复制到其他项目。

01

设计概览

四条原则决定这套界面的取舍：信息优先、层级克制、操作可预期、桌面与手机同源。

信息优先

列表与看板先回答“现在怎么样”，再提供操作。数据用字重和字号建立层级，不依赖大面积色块；颜色只用于状态、趋势与主操作。

层级克制

一张页面最多一个主按钮；卡片只用一层阴影；分割线优先于边框；强调色只出现在品牌、链接、选中态和关键数字上。

操作可预期

主操作固定在右侧或底部；危险操作使用红色文字按钮并二次确认；筛选、分页、空态位置在所有列表页保持一致。

双端同源

不为手机复制第二套页面：同一套组件通过断点收敛列、宽度与间距。桌面保留完整信息，手机保留关键指标与操作。

按钮与操作

一个区域只有一个主按钮。主操作用实心蓝，次操作用描边，危险操作使用浅红底或红色文字。

主按钮 / 次按钮 / 危险按钮
尺寸与禁用态
DO列表页把“新建 / 导入”放在工具栏右侧；行内操作使用文字按钮，右对齐。
DON'T同一行放两个实心主按钮；也不要给“取消”加主色，它应该是描边或文字按钮。

可用性与可访问性

对比度、焦点、动效与文案密度，是这套规范在真实项目中不出问题的底线。

主文字 / 白底#0F172A · 17.9:1 · AAA
辅助文字 / 白底#64748B · 4.8:1 · AA
白字 / 主色按钮#FFFFFF on #2563EB · 5.2:1 · AA
弱提示 / 白底#94A3B8 · 2.6:1 · 仅辅助信息
焦点态主色描边 + 3px rgba(37,99,235,.12)
动效0.2s ease；尊重 reduced-motion
DO状态同时用颜色 + 文案表达；图表提供数值标签；移动端热区不小于 44px。
DON'T不要只用颜色区分对错；不要把 #94A3B8 用在正文；不要用弹窗展示字段级校验。
14

工程接入

tokens.css 提供全部变量，components.css 提供组件类；Element Plus 项目会自动映射主题色与圆角。

1. 引入令牌与组件
/* main.js / main.ts */
import './styles/tokens.css';      /* 变量层 */
import './styles/components.css';  /* 组件层：ui- 前缀 */
import './styles/app.css';         /* 业务层：只做组合 */

/* 业务样式只引用变量 */
.panel {
  background: var(--ui-surface);
  border: 1px solid var(--ui-border);
  border-radius: var(--ui-radius-lg);
  box-shadow: var(--ui-shadow-card);
}
2. Tailwind 映射
// tailwind.config.js
theme: {
  extend: {
    colors: {
      brand: {
        100: '#EFF6FF',
        400: '#5B8BF5',
        600: '#2563EB',
        700: '#1D4ED8'
      },
      surface: '#FFFFFF',
      canvas: '#F4F6FB'
    },
    borderRadius: { lg: '14px', md: '10px' },
    boxShadow: {
      card: '0 1px 2px rgba(15,23,42,.04), 0 8px 24px rgba(15,23,42,.04)'
    }
  }
}
3. 断点约定
/* 与现有后台保持一致 */
@media (max-width: 1300px) { /* KPI 两列 */ }
@media (max-width: 900px)  { /* 侧栏抽屉 */ }
@media (max-width: 768px)  { /* 表单/表格移动态 */ }

/* 移动端基准视口 */
/* 390 × 844 */
4. 使用约束
颜色禁止在业务代码写死 hex，统一引用 --ui-*
圆角面板 14 / 控件 8 / 标签 6，不新增中间值
字号正文 13–14 / 辅助 12 / 微文案 11
阴影一个页面不超过 2 种阴影
主色仅主操作、链接、选中态、关键数字

与 Element Plus 的关系

不替代、不重绘。两种用法按项目现状选择：

已用 El Plus根容器加 ui-scope，统一表头、抽屉、分页的尺寸密度
原生 / 自研直接用 ui- 类，无需引入组件库
Tailwind 项目用 tokens 生成 theme，组件类按需取舍
小程序 / 移动端复用数值与状态规则，类名改为 rpx 实现
约定：components.css 不写 !important，不覆盖 .el-* 全局样式，只在 .ui-scope 内做密度修正。
