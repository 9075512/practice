摘要与概览

先看结论：这套体系解决什么问题、由什么构成、目前完成到什么程度。

四条设计结论

决定这套界面取舍的核心判断

  • 信息优先：先回答「现在怎么样」，再提供操作；用字号与字重建层级，不靠大面积色块。
  • 层级克制：一屏一个主按钮、一层阴影、一套圆角，颜色只用于状态与主操作。
  • 双端同源：不为手机复制第二套页面，靠断点收敛列、宽度与间距。
  • 令牌先行：颜色、间距、圆角、阴影全部变量化，业务代码不写死 hex。

05

响应式策略

一套代码适配桌面与手机：只收敛列宽、间距与浮层宽度，不复制第二套页面。

5.1 断点与变化

四个断点，四类变化；移动端基准视口 390 × 844

断点布局变化
≥ 1300px桌面完整态侧边栏 232 固定，KPI 四列，表格显示全部列
900 – 1300px桌面紧凑态KPI 两列，图表图例与轴名进入 compact 模式
≤ 900px平板 / 窄窗侧边栏收起为抽屉，导航栏出现菜单按钮，内容边距压缩
≤ 768px手机工具栏铺满、表格隐藏次要列并横向滚动、抽屉全屏、弹窗 92%、图表 240px
桌面 · 1440px
手机 · 390px
桌面保留 4 列 KPI 与完整表格；手机改为 2 列 KPI、图表压缩高度、表格只保留关键列并由容器横向滚动。

5.2 移动端处理规则

按优先级从高到低

  • 先隐藏次要列，再考虑压缩字号；字号不随屏宽变小。
  • 工具栏控件铺满宽度，搜索框占满一整行。
  • 抽屉全屏、弹窗 92% 宽，表单改单列。
  • 图表只保留一条主线与必要坐标轴，图例移到顶部。
  • 分页居中，页码只留上一页 / 当前 / 下一页。

5.3 桌面端不可牺牲项

缩到 900px 前必须保留的能力

  • 批量选择与批量删除入口。
  • 表格排序、筛选与列宽信息。
  • 抽屉内表单的完整字段与校验。
  • 图表的时间范围切换与数值提示。
  • 键盘操作路径与焦点顺序。

07

落地清单

复制两个文件、按顺序引入，即可在新项目获得同一套视觉；组件按需取用，不强制全量。

7.1 文件与引入顺序

令牌必须先于组件，组件先于业务样式

文件作用
tokens.css128 项变量 + 基础元素 + Element Plus 映射
components.css25 个组件，约 34 KB 未压缩
app.css业务布局与页面级样式
Vue / React 在入口文件按 token → components → app 的顺序 import；Element Plus 项目根容器加 ui-scope。

7.2 上线前检查

每条都可直接判定

  • 业务样式无硬编码 hex，全部引用 --ui-*。
  • 一屏只有一个主按钮，危险操作有二次确认。
  • 列表页具备加载、空态、错误三态。
  • 390px 下无横向滚动、无遮挡、无文字竖排。
  • 所有可交互元素键盘可达，焦点可见。
